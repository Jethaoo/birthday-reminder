# Commit, push, PR

Do only the steps the user asked for: "commit" means commit, "push" means push, "PR" means create the
pull request. Stop and report rather than forcing past a failed step.

## 0. Preflight

```powershell
git status --short --branch
git remote -v
gh auth status
```

- **Never commit directly to `main`.** If the current branch is `main`, create `fix/<thing>` or
  `feat/<thing>` first (`git switch -c feat/photos`), and say so. Only commit to `main` when the user
  explicitly asks for it.
- **Base branch is `main`** — the repo default and where recent PRs land. `CONTRIBUTING.md` still
  says branch off `develop`, but `origin/develop` sits 8 commits behind `main` with nothing unique;
  use `develop` only when the user names it, and fetch it before branching.
- `gh` may not be authenticated. If `gh auth status` fails, never start an interactive login: push,
  then print the compare URL from step 6 and tell the user to run `gh auth login` once.

## 1. Inspect the change

```powershell
git status --short
git diff
git diff --staged
```

- Stage only the files that belong to the requested change. Leave unrelated edits untouched and list
  them in the final report.
- Mixed concerns become separate commits, not one large sweep. Ask before splitting work the user
  described as a single change.
- Scan the diff for anything that must never be committed: `.dev.vars*`, `.env*`, `*.jks`,
  `*.keystore`, `key.properties`, `**/*firebase-adminsdk*.json`, `**/*-adminsdk-*.json`,
  `google-services.json`, `*.pem`, `*.key`. If one is staged, unstage it and stop.
- Do not `git add -A` while unrelated or ignored-looking files are in the tree; name paths.

## 2. Changelog gate

CI's **Changelog updated** job fails any PR that does not touch `CHANGELOG.md` under
`## [Unreleased]`, unless the PR carries the `skip-changelog` label (Dependabot is exempt).

- User-visible or deployer-visible change → add the entry in the same commit as the code, naming the
  affected area:

  ```markdown
  - **app:** Photos can come from the camera or the library.
  - **backend:** `0003_user_profile.sql` adds the profile photo columns.
  ```

  Existing sections in use: `Added`, `Changed`, `Fixed`, `Security`, `Removed`, `Upgrade notes`.
- Chore, refactor, CI or docs-only PR with nothing to announce → keep `CHANGELOG.md` untouched and
  label the PR `skip-changelog` (`gh pr create --label skip-changelog`, or
  `gh pr edit <number> --add-label skip-changelog`).
- State which branch of this rule you took in the final report.

## 3. Checks

Run the checks for what changed. A red check blocks the commit unless the user explicitly accepts it.

| Changed paths | Command (stops at the first failure) |
|---|---|
| `backend/` | `cd backend && pnpm typecheck && pnpm lint && pnpm test` |
| `app/` | `cd app && flutter analyze && flutter test` |
| `design/` | `cd design && pnpm exec tsc --noEmit && pnpm build` |
| docs, CI, `.dsh/` only | none |

When unsure which area changed, run all three. Report which commands ran, not just "tests pass".

## 4. Commit

```powershell
git add app/lib/features/photos app/pubspec.yaml app/test/widget/photo_source_sheet_test.dart
git diff --staged --stat
```

Write the message in the imperative, ≤ 72 characters, optionally conventional-prefixed with an area:

```text
feat(app): crop photos to a square before upload
fix(backend): preserve the unique dedupe key across retries
chore: bump wrangler
```

Add a short body for the *why* when the subject cannot carry it (`git commit -m "subject" -m "body"`).
No tool or "generated by" attribution unless the user asks.

## 5. Push

```powershell
git push -u origin HEAD
```

- Never push to `main` or `develop`; never use plain `--force`.
- Push rejected because the branch is behind → `git pull --rebase` and retry. On a conflict, stop and
  report instead of inventing a resolution.
- Rewriting an already-pushed branch needs explicit approval, then `--force-with-lease` only.
- If push fails on credentials, stop and quote the exact error: the HTTPS remote uses the Git
  Credential Manager, which may need an interactive prompt.

## 6. Pull request

With `gh` authenticated, write the body to a temp file — never inside the repo — such as
`$env:TEMP\dsh-pr-body.md` on Windows or `/tmp/dsh-pr-body.md` elsewhere, then:

```powershell
gh pr create --base main --head <branch> --title "feat(app): crop photos to a square" --body-file "$env:TEMP\dsh-pr-body.md"
```

Body format:

```markdown
## Summary

One or two sentences on what changed and why.

## Changes

- **app:** ...
- **backend:** ...

## Testing

- Ran `flutter analyze`, `flutter test`
- Not run: ...

## Notes

Migrations, secrets, manual steps, or "None".

[![](https://img.shields.io/badge/powered_by-dsh-4D6BFE?style=flat-square&logo=deepseek&logoColor=white)](https://github.com/deepseek-ai/deepseek-harness)
```

Add `--draft` only when the user asks. Use `--label skip-changelog` when step 2 chose that route.

Without `gh` auth, do not treat the PR as blocked — push, then print the compare URL built from
`git remote get-url origin`:

```text
https://github.com/<owner>/<repo>/compare/main...<branch>?expand=1
```

Tell the user to open it, and that `gh auth login` enables automatic creation next time.

## 7. Verify and report

```powershell
gh pr view --json url,number,state,mergeable,statusCheckRollup
```

Report the PR number and URL, its base branch, the commit subject(s), the checks that ran, the
changelog decision, and anything left undone (unrelated working-tree edits, skipped checks). Do not
merge unless the user asks; if asked, confirm squash versus merge commit first.

## Stop conditions

- A check fails and the user has not accepted it.
- A secret or signing key is staged.
- Push is rejected by branch protection or a non-fast-forward conflict.
- `gh` is unauthenticated — the PR is reported as a compare URL, not retried.
